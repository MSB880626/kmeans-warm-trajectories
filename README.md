# Monotone Warm-Started K-Means Trajectories in Apache Spark

Code, experiment scripts and raw results for the paper

> M. Sánchez-Brito. *Monotone Warm-Started K-Means Trajectories: A Divisive Approach Implemented in Apache Spark.* (submitted).

The method computes the complete trajectory of k-means solutions for k = 1, …, k_max in Apache Spark.
At each step it splits the cluster with the largest expected reduction of the within-cluster sum of
squares along its principal eigenvector, refines all centers with a global Lloyd run, and applies an
acceptance rule with an additive fallback that guarantees W(k + 1) ≤ W(k) for every k, whatever the
stopping rule of Lloyd's algorithm.

## Contents

| Path | Description |
|---|---|
| `crira_dk.py` | Distributed Lloyd engine, proposed method (`--inits warm`), baselines (`kmeansll`, `incpp`, `mllib_kmeans`, `mllib_bisecting`), selection criteria (gap, CH, silhouettes) and metrics. |
| `ejecutar_experimentos.sh` | Experiment campaigns used in the paper (blocks `kaggle_*`). |
| `analizar_crira_dk.py` | Optional statistical analysis of a campaign (hierarchical bootstrap, paired non-inferiority). |
| `results/` | Raw CSV and JSON outputs of every run reported in the paper. |
| `paper_figures/make_figures.py` | Regenerates Figures 1–6 of the paper from `results/`. |
| `figures/` | Figures produced by `make_figures.py`. |

Comments and log messages in the source code are in Spanish; command-line options and output columns are in English or self-explanatory.

## Requirements

Python ≥ 3.10, Java 17 or 21, and the packages in `requirements.txt`:

```bash
pip install -r requirements.txt
```

The experiments of the paper were run with Spark 4.0.4 (local mode, 4 threads), Python 3.13, NumPy 2.1.3 and pandas 2.3.3 on a 4-core Kaggle notebook with 32 GB of memory.

## Quick start

Trajectory for k = 1, …, 20 on a synthetic Gaussian mixture, comparing restarted k-means|| with the proposed method:

```bash
python crira_dk.py --master "local[4]" --n 200000 --d 10 --k-true 8 --sep 4 \
  --kmax 20 --seeds 0 --inits kmeansll warm --criteria gap ch sil \
  --gap-B 3 --gap-ref-n 20000 --partitions 16 --out res/demo
```

Each run writes

* `<out>.csv`: one row per method, seed and selection criterion (selected k, ARI/NMI, time, passes, monotonicity violations, fallbacks, …);
* `<out>_path.csv`: one row per method, seed and k (W(k), Lloyd iterations, time, passes, cost of the seed, fallback flag);
* `<out>_env_<config_hash>.json`: environment, arguments and SHA-256 of the code.

Real data in CSV or Parquet: `--data real --path file.csv --label-col _c0` (columns are standardized unless `--no-standardize`).

Main options: `--conv {sklearn,both,shift}` (stopping rule, default `sklearn`), `--max-iter 50`, `--tol 1e-4`, `--split-cands 3` (number of candidate clusters m), `--dtype {float32,float64}`.

## Reproducing the experiments

```bash
export MEM=10g OUT=res
DS=101 bash ejecutar_experimentos.sh kaggle_calidad   # Sections 4.1, 4.2, 4.7  (12 synthetic scenarios)
bash ejecutar_experimentos.sh kaggle_ablacion          # Section 4.3
bash ejecutar_experimentos.sh kaggle_sensibilidad      # Section 4.4  (three stopping rules)
bash ejecutar_experimentos.sh kaggle_mllib             # Section 4.5
DATOS=./datos bash ejecutar_experimentos.sh kaggle_reales   # Section 4.6  (downloads Covertype, SUSY, HIGGS from UCI into DATOS)
python paper_figures/make_figures.py                   # Figures 1–6
```

Each block stops starting new runs after `BUDGET_H` hours (default 10.5) so that it fits in a 12-hour Kaggle session.
Runs already present in `OUT` with the same configuration and seeds are skipped.

## Code versions

Every CSV row and JSON file records the SHA-256 of the code that produced it (`code_sha`, `sha256_crira_dk`).

| SHA-256 (prefix) | Used for | Difference with respect to the previous version |
|---|---|---|
| `43e8e6ca` | Quality experiment; real data, seed 0 | — |
| `f0344dcb` | Covertype, seeds 1–2 | Adds the Euclidean silhouette on a sample (`sile`); trajectories identical |
| `43b8d315` | Ablation, stopping rule, MLlib | Fixes a negative random seed in the `sile` sampler; trajectories identical |
| current | — | Acceptance test without the relative tolerance of 1e-12 (fallback whenever the seed cost exceeds W(k)) |

The trajectories produced by the proposed method are identical across the three versions used in the paper.
In the 953 steps reported in the paper, no accepted split seed had a cost above W(k), so the current strict acceptance test produces the same results.

## Data

* Covertype, SUSY and HIGGS: UCI Machine Learning Repository (downloaded automatically by `kaggle_reales`). SUSY and HIGGS were sampled at 40% and 10% with `--data-seed 7`.
* Synthetic data are generated by `crira_dk.py` from the parameters and seeds stored in each JSON file.
